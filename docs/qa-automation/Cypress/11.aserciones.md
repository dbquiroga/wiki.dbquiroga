title: Aserciones
---

Las aserciones se usan para comparar lo que se espera que ocurra con el resultado actual. Son las que validan si una prueba pasó o falló.

Cypress no tiene su propia librería de aserciones, para eso utiliza **Chai**, que tiene dos estilos:

- **BDD**: basadas en el comportamiento (`.should`, `.expect`)
- **TDD**: basadas en el resultado del caso de prueba (`.assert`)

## Aserciones más comunes

| Aserción | Cuándo usarla |
|---|---|
| `should` | Elementos web. Encadena directamente sobre el comando Cypress. |
| `assert` | Verificaciones de valores en variables. |
| `expect` | APIs y valores no-DOM. Requiere `.invoke()` para elementos web. |
| `have.text` | Verificar el texto visible de un elemento. |
| `have.css` | Verificar propiedades de estilo. |

### Encadenar aserciones con `.should` y `.and()`

```js title="Verificar texto y visibilidad"
cy.get('.mensaje')
  .should('be.visible')
  .and('have.text', 'Bienvenido')
```

```js title="Verificar valor de un input"
cy.get('#email').should('have.value', 'test@ejemplo.com')
```

:::note
Cypress no tiene **soft assertions**: si una aserción falla, el test se detiene en ese punto y no continúa.
:::
